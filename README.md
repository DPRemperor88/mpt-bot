# mpt-bot

Telegram-бот расписания и домашних заданий одной студенческой группы МПТ
(Московский приборостроительный техникум).

## Возможности

- Расписание на сегодня и завтра, числитель / знаменатель, время пар.
- Замены с сайта МПТ: отдельные даты на одной странице, уведомления о новых,
  исправленных и снятых заменах.
- ДЗ на сегодня, завтра и все предстоящие задания; несколько заданий по одному
  предмету и несколько фото / документов, в том числе присланных альбомом.
- Добавление и удаление ДЗ модераторами и администраторами.
- Утренняя отправка расписания за час до первой действующей пары текущей недели.
- Настройки уведомлений в личке: новое ДЗ, замены, утреннее расписание.
- Групповые чаты: выдача ДЗ по командам, уведомления о заменах и утреннее расписание.
- Админ-панель: участники, журнал действий, назначение модераторов и рассылка.
  Длинные списки панели доступны по страницам.

## Запуск

Проверяемые в CI версии Python: 3.11–3.13. Docker использует Python 3.12.

```bash
python -m venv .venv
```

Активируйте окружение:

```powershell
# Windows / PowerShell
.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

```bash
# Linux / macOS
source .venv/bin/activate
cp .env.example .env
```

Заполните `BOT_TOKEN` и `ADMIN_IDS` в `.env`, проверьте `GROUP_NAME` в `config.py`:

```bash
pip install -r requirements.txt
python main.py
```

`requirements.txt` подключает `requirements.lock` с точными версиями прямых
и транзитивных зависимостей. Обновляйте lock-файл вместе с проверками.
Токен храните только в `.env`, не в исходниках.

Docker:

```bash
docker compose up -d --build
```

Обновление сервера и резервное копирование описаны в [DEPLOY.md](DEPLOY.md).

## Настройка

В `.env`:

| Параметр | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `ADMIN_IDS` | Telegram ID главных администраторов через запятую |
| `DATABASE_URL` | По умолчанию SQLite `bot.db`; в Docker `/data/bot.db` |

В `config.py`:

| Параметр | Назначение |
|---|---|
| `GROUP_NAME` | Точное название группы на сайте |
| `CALL_SCHEDULE` | Время каждой пары |
| `WEEK_COLOR_MAP` | Соответствие цветов числителю и знаменателю |
| `TIMEZONE` | Часовой пояс, по умолчанию `Europe/Moscow` |
| `HOMEWORK_CLOSE_HOUR` | Час скрытия ДЗ в день сдачи, по умолчанию 20:00 |
| `SCHEDULE_REFRESH_MINUTES` | Проверка расписания, по умолчанию 180 минут |
| `CHANGES_REFRESH_MINUTES` | Проверка замен, по умолчанию 15 минут |
| `THROTTLE_SECONDS` | Интервал между командами и кнопками; ввод ДЗ и файлы не отбрасываются |

## Команды и роли

В личном чате:

- `/start`, `/menu` — главное меню и сброс текущего сценария ввода.
- `/cancel` — отмена текущего ввода и возврат в меню.
- `/admin` — панель модератора / администратора.

В групповом чате:

- `/start`, `/menu` — меню ДЗ.
- `/today`, `/tomorrow` — ДЗ на сегодня / завтра.

| Действие | Студент | Модератор | Администратор |
|---|---|---|---|
| Расписание, ДЗ, личные настройки уведомлений | Да | Да | Да |
| Добавление и удаление ДЗ, участники, журнал | — | Да | Да |
| Назначение модераторов, рассылка | — | — | Да |

Права проверяются на каждом шаге административного сценария, включая сохранение
ДЗ, назначение модератора и запуск рассылки. ДЗ после установленного часа скрываются
из разделов заданий, но остаются в расписании. Ручной отметки «выполнено» нет.

## Надёжность и ограничения

- Неизвестная структура страницы, недоступность сайта или неопределённая неделя
  не затирают последний корректный кэш. В расписании указано время обновления.
  На холодном старте без кэша сайт должен быть доступен.
- Первый снимок замен сохраняется без уведомления об уже опубликованных заменах.
  Исчезновение старого раздела даты не считается отменой: снятие замены определяется
  только для дат, которые продолжают присутствовать на странице.
- Утреннее расписание и выбор дат ДЗ используют пары нужной недели, исключая явно
  отменённые занятия. Неструктурированный текст остальных замен показывается
  дословно; бот не угадывает переносы и преподавателей по произвольной фразе.
- ДЗ, вложения, запись журнала и очередь уведомлений сохраняются одной транзакцией.
  Снимок замен и соответствующая очередь также сохраняются атомарно.
- Очередь `deliveries` хранится в SQLite и проверяется каждые 10 секунд.
  Отправленные части сообщения не повторяются при обычном возобновлении.
  Сетевые / серверные ошибки повторяются с задержкой до часа, Telegram `retry_after`
  приостанавливает worker. Порядок уведомлений одному получателю сохраняется.
- Блокировка бота и некорректный запрос прекращают конкретную доставку со статусом
  `failed`; причина доступна в `deliveries.last_error` и логах сервера.
  Доставка не имеет гарантии exactly-once: при обрыве после принятия сообщения
  Telegram, но до записи результата в SQLite, возможен повтор.
- HTML из имён, ДЗ и сайта экранируется. Длинные сообщения разбиваются с сохранением
  разметки; вложения административной рассылки отправляются после текста.
- Бот рассчитан на один процесс. FSM и состояние экранов хранятся в памяти:
  несохранённый черновик теряется при перезапуске. Полученные альбомы обрабатываются
  последовательно в рамках FSM. Сохранённые ДЗ и очередь переживают перезапуск.
- Старые версии БД обновляются при запуске через последовательные миграции
  `database/migrations.py`. Рабочие данные сохраняются; перед обновлением сделайте
  резервную копию. Старый код не следует запускать на новой схеме.
- История доставок сохраняется в БД. Автоматическая очистка истории не настроена.

## Проверки

```bash
python -m pip check
python -m unittest discover -s tests -v
```

Тесты используют отдельные временные SQLite-базы, локальные HTML-примеры и
заглушки Telegram. Рабочий токен, сеть и `bot.db` для них не нужны.
GitHub Actions выполняет проверки при push и pull request.

Покрыты: несколько дат замен, повтор замены на новую дату, исправление / снятие
замены, некорректный HTML, чётность недели, отмена первой пары, несколько ДЗ на
предмет, загрузка альбома, отзыв прав, сброс FSM, разбиение HTML, атомарность
сохранения, повтор доставки, порядок уведомлений и обновление старой БД.

## Структура

```text
main.py                 aiogram, планировщик, ограничение частоты команд
config.py               конфигурация
parser.py               расписание и чётность недель
parser_changes.py       замены с привязкой каждой записи к дате
services.py             расписание, ДЗ, подготовка уведомлений
delivery.py             HTML-разбиение и worker сохраняемой очереди
ui.py, keyboards.py     экраны и клавиатуры
utils.py                форматирование и экранирование
database/               модели, CRUD, миграции
handlers/               личка, группы, админ-панель
tests/                  регрессионные тесты и HTML-примеры
.github/workflows/      автоматические проверки
```
